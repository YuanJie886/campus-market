# 微信小程序第一版验证记录

日期：2026-10-09。工程：`campus-market-miniapp/`。验证使用 Node 24、本机 Chrome 手机尺寸预览；默认模式为本地演示。

## 已通过

- TypeScript 类型检查。
- 10 项业务与请求层测试：学校边界、商品级联系方式授权、重复申请、卖家审批、拒绝、收藏隔离、发布与状态管理；并发令牌刷新、刷新 Cookie 作用域、轮换、退出、网络与限流处理、真实接口路径。
- 微信生产构建，演示及 REST 两种模式均可编译；7 个页面的 JS、JSON、WXML 和底部导航图标齐全。交付目录 `dist/` 保持默认演示模式。
- H5 生产构建。Webpack 保留预览资源体积提示，构建成功。
- 390 × 844 手机预览：全部 8 件演示商品配图加载成功；页面无横向溢出。
- 浏览器实际交互：登录 → 搜索 → 收藏 → 申请联系 → 切换卖家 → 同意申请 → 切回买家查看获准联系方式 → 收藏列表。
- 浏览器实际交互：发布 → 编辑 → 下架 → 重新上架 → 标记已售 → 刷新后数据保留。
- 上述浏览器流程没有页面 JavaScript 运行错误。
- 微信官方 `wcsc` 编译检查：复现并修正中文 CSS 类名导致的 `unexpected` 错误，改用英文分类样式标识；修复后全量 WXSS 编译通过。可运行 `npm run check:wxss` 复查。

## 尚未验证或交付

- 已在本机用微信官方 WXSS 编译器验证；由于界面控制权限未授予，尚未由本次自动检查确认模拟器的最终显示，微信真机也未验证。样式编译通过不能替代完整原生验证。
- REST 适配已与当前接口定义核对并测试请求路径，但没有完成真实后端端到端联调。
- 微信 code 登录与账号关联、真实 AppID 配置、后端图片存储服务尚未实现。原生 REST 冷启动需要重新输入平台账号。
- 真机分享、相册 / 相机权限、后台恢复、弱网与上线审核仍需联调。
- 没有发布、部署或更改真实业务数据；演示商品与账号是本机虚构数据。
