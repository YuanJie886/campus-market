## 3. 真实浏览器 E2E（8.1）

- 工具：Playwright 1.63（`@playwright/test`，锁文件已更新）；本机用已安装的 Google Chrome（`channel=chrome`，没有下载浏览器）；CI 用 Playwright 自带的 Chromium。
- 测试栈：前端 REST 构建 + 后端 jar + 一次性 PostgreSQL 16（`e2e/stack/*`）；MockMvc、jsdom、直接调用接口都**不算**在这里。
- 隔离：每个参与方一个独立的 browser context；账号每次随机；除本机测试栈外的网络请求全部拦截。
- 失败产物：截图（确认码区域打码）+ 脱敏 trace（删除网络记录与响应体、替换本次的密码 / 令牌 / Cookie / 邀请码 / 确认码与任何 JWT）；
  Playwright 自动生成的文本附件由 `e2e/redact-reporter.ts` 再脱敏。
- 结果：**16/16 通过，连续两次**（`npm run e2e` 与 `npx playwright test`）；结束后没有残留容器或卷。

## 5. 8.1 / 8.2 发现并修复的缺陷

| 缺陷 | 影响 | 修复 | 回归测试 |
|---|---|---|---|

## 7. 真实图片上传：方案（未实现，等待批准）

不擅自开通任何云存储。建议方案：

1. **存储**：学校或部署方自有的 S3 兼容对象存储（例如自建 MinIO 或已有的对象存储），按学校分前缀；不放在 API 容器本地磁盘。
2. **上传**：后端签发短时效、单对象的预签名上传地址（限定 `Content-Type` 与大小，例如 ≤ 5 MB、最多 9 张）；前端直传；上传完成后后端登记并校验。
3. **处理**：服务端重新编码（去除 EXIF 定位等元数据）、生成缩略图；拒绝非图片内容；登记 SHA-256 以便重复检测与治理。
4. **访问**：图片地址不可枚举；私密圈子商品的图片只对可读用户签发短时效读取地址；商品被治理隐藏时图片同样不可读。
5. **治理与删除**：商品删除 / 隐藏时同步处置图片；新增「隐藏图片」动作时同步 DB CHECK、接口、Mock、界面与文档。
6. **过渡**：批准前继续只允许示例图，并在发布页如实说明（已有「演示版使用预置图片，不支持真实文件上传」）；公开上线前必须完成。
