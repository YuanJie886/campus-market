# 运维与监控准备（阶段 6，本地可做的部分）

> 状态日期：2026-10-19。本文只整理**仓库里已经有的**运维抓手和上线前要在真实环境完成的事项。
> 没有开通任何服务器、域名、监控或告警服务；下面列出的「上线前必须」都还没有做。

## 1. 已有的抓手

| 抓手 | 位置 | 用法 |
|---|---|---|
| 健康检查 | `GET /v1/health`（会访问一次数据库） | 外部探活与负载均衡检查；经 nginx 同样可达 |
| 请求编号 | nginx 生成，响应头 `X-Request-ID`、错误响应体里的 `requestId`、nginx 访问日志 `rid=`、API 日志 `requestId=` 是同一个值 | 用户反馈问题时让其提供编号，按编号查两边日志 |
| 日志轮转 | 编排里每个容器 json-file 5 × 10 MB；访问日志不记录查询参数 | 长期保存需接入日志服务，保留期写进隐私政策（【日志保留天数】） |
| 冒烟压测 | `deploy/loadtest/load-smoke.mjs`（只能对本机或测试环境；非本机地址需 `--test-environment`）；演练里 `DRILL_LOAD=1` | 目标：读接口 p95 < 500 ms、错误率 < 1% |
| 容器自恢复 | 编排里各服务 `restart: unless-stopped`；数据库 `pg_isready` 健康检查 | 进程崩溃自动拉起 |
| 安全响应头 | `campus-market-frontend/deploy/nginx/security-headers.conf`（Web 与后台共用） | 部署演练逐项检查 |
| 限流 | 数据库固定窗口，按主体与范围（登录、联系申请、图片上传、后台读写等） | 被刷时先看 `rate_limit` 相关表的计数 |
| 审计 | 工作人员写操作、后台读操作（搜索词只存哈希）、角色变更双人确认、账号注销、历史交易收口、内容安全事件 | 都禁止删除与截断，可直接用 SQL 复核 |
| 备份 | `docs/backup-and-restore.md`（数据库 + 上传图片卷） | 恢复演练见该文 |
| 部署演练 | `campus-market-frontend/deploy/drill/local-deploy-drill.mjs` | 本机全链路：迁移、代理、响应头、图片上传与持久化、重启保留 |

## 2. 建议监控的信号（上线前接入）

| 信号 | 来源 | 建议阈值（试运行期，按实际调整） |
|---|---|---|
| 探活失败 | `GET /v1/health` 每分钟 | 连续 3 次失败告警 |
| 5xx 比例 | nginx 访问日志 | 5 分钟内 > 1% 告警 |
| 429 突增 | nginx 访问日志 | 单一路径 5 分钟内 > 100 次关注 |
| 内容安全拦截 | `SELECT scene, provider, verdict, count(*) FROM content_safety_events WHERE created_at > now() - interval '1 day' GROUP BY 1,2,3` | 每日查看；微信 `REVIEW` 需人工过一遍 |
| 微信接口不可用 | 应用日志里的内容安全告警 | 出现即关注（此时只剩关键词过滤） |
| 待处理举报 / 申诉积压 | 治理案件表 OPEN 数量 | 超过 24 小时未处理关注 |
| 磁盘 | 数据库卷与图片卷 | 使用率 > 80% 告警 |
| 备份 | 每日备份文件存在且非空、每月恢复演练 | 缺失即告警 |

## 3. 日志规范（已执行，接入日志服务时保持）

- 日志里不出现令牌、密码、重置码、Cookie、联系方式、内容安全原文；测试 `ContentSafetyIT` 校验原文不进日志。
- 日志保留期与访问权限需写进隐私政策；建议应用日志保留 30 天、审计表长期保留。

## 4. 上线前必须在真实环境完成（未做）

1. 服务器、域名、ICP 备案、HTTPS 证书（含自动续期）；小程序后台配置 request / uploadFile 合法域名。
2. 生产环境变量：数据库口令、JWT 密钥、微信 AppID / AppSecret 用密钥管理注入，不进仓库、不进镜像。
3. 接入上面第 2 节的监控与告警，指定值班人与联系方式。
4. 每日自动备份 + 异地副本；做一次真实的恢复演练并记录耗时。
5. 压测：在目标服务器的测试环境上运行 `node deploy/loadtest/load-smoke.mjs https://<测试域名> --test-environment --concurrency 50 --seconds 300`（按试点规模调整），记录 p95 与数据库连接数；本机演练的数字只作基线参考。
6. 导入真实学校与楼栋数据（不使用真实用户数据做测试）。
7. 图片对象存储（如需要）：新增 `ImageStore` 实现即可，签名与可见性逻辑不变。
