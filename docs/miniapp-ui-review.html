校园集市小程序
界面评审与优化方案

评审对象为 Taro 4.3 + React 的微信小程序端，共 7 个页面、1 份全局样式（app.scss，159 行）。评审围绕信息层级、可读性、交互成本、设计系统一致性、可达性五个维度展开，并给出可直接落地的改版稿与样式映射。

01

总体判断

视觉方向是对的——松绿 + 米白的克制配色在一众高饱和二手平台里有辨识度，文案也克制、可信。问题集中在「执行层的精细度」：字号与对比度没到真机可读的底线，交互把高频动作藏进了折叠面板，以及缺少 token 层导致同一套界面里出现 14 档字号、9 档圆角。

02

问题清单

按修复优先级排列。P0 是「用户会直接感知到坏」的缺陷，P1 影响转化与效率，P2 是打磨项。

P0

必须修

4 项 · 纯样式，不改逻辑
P0-01

辅助文字只有 9px，对比度 2.5:1，真机上等于不可读

app.scss:73.card-meta{font-size:9px;color:#78907d}app.scss:79.card-time{font-size:9px;color:#a0a69b}

#a0a69b 在白底上的对比度仅 2.49:1，#78907d 为 3.46:1，都远低于 WCAG AA 要求的 4.5:1。9px 在 375pt 屏上约等于 9 CSS px，中文笔画会糊成一团——商品卡上的「分类 / 校区 / 发布时间」这行信息实际上被浪费了。

辅助信息统一提到 11px，颜色改为 --ink-500 #5E6B63（对比度 5.1:1）。全局禁用 9px 与 10px。

P0-02

字重用了 550 / 650，iOS 上不生效，实际渲染不可控

app.scss:14font-weight:650app.scss:74550app.scss:76650app.scss:86,146550

PingFang SC 只提供 300 / 400 / 500 / 600 / 700 五档。550、650 会被系统就近吸附或直接忽略，安卓与 iOS 的吸附规则还不一致——同一套设计稿在两台手机上标题粗细不同，视觉层级就散了。

字重收敛为 400 / 500 / 600 / 700 四档。标题 600、价格 700、按钮 600、正文 400。

P0-03

多个可点区域的触控尺寸低于 44×44pt

app.scss:68.favorite{width:32px;height:32px}app.scss:31.text-action{font-size:12px}app.scss:102.remove-photo{22px}

商品卡收藏按钮 32px、图片删除按钮 22px、「清空筛选 / 编辑资料」这类纯文字链接没有 padding。微信设计指南要求热区不小于 40×40，Apple 要求 44×44。收藏是首页最高频的轻交互，32px 会明显误触到卡片跳转。

视觉尺寸可保持 32–34px，但用 ::after 撑出 44×44 的透明热区；文字链接补 padding:8px 并负 margin 抵消占位。

P0-04

语义色缺失：「已同意」和「未同意」是同一个绿色

app.scss:123.status-pill{color:#52714a;background:#eef2e7}notifications/index.tsx:37

申请卡片的 labels 有 PENDING / APPROVED / REJECTED 三种状态，但都套用同一个 .status-pill。用户扫一眼列表，无法区分「等着我处理」和「已经拒绝」，只能逐个读文字。同理「已售出 / 已下架」在详情页也是绿色。

建语义色板：待处理 琥珀 #A56A12、已同意 绿 #2F6B4F、未同意 / 已下架 中性灰 #68736B、已售出 灰。状态色必须与状态文案同时出现，不单靠颜色。

P1

影响转化与效率

7 项 · 需小改结构
P1-01

首屏 110px 给了纯装饰的 banner，商品被挤到第二屏

market/index.tsx:42.intro · app.scss:39-42

深绿渐变卡里有 21px 标题 + 说明 + 演示 badge，但它不承载任何操作，也不随用户状态变化。在 375×667 的机型上，这块占掉首屏近 1/5，结果只露出 1.5 行商品。

删掉 banner，把搜索框提到导航栏下方并做成 sticky；品牌感交给配色和导航栏标题，不用大色块换空间。

P1-02

排序藏在折叠面板里，改一次排序要三步

market/index.tsx:45,50

点「筛选与排序 ⌄」→ 展开面板 → 点 Picker → 底部弹窗滚动 → 确定。而分类 tab 与筛选面板里的排序项还重复了一次。列表页排序是高频动作，这个成本不合理。

排序改为结果行上方的常驻 tab（综合 / 最新 / 价格↑↓），筛选收进右侧独立按钮 + 已选条件计数角标。

P1-03

发布页是 12+ 字段的单页长表单

publish/index.tsx:76-91

图片、名称、描述、价格、原价、分类、成色、校区、联系方式、公开开关，再加 3–6 项「商品情况」声明，全部堆在一张卡片里，首屏看不到价格，提交按钮在 3–4 屏之外。发布是供给侧的入口，这个长度会直接压掉发布完成率。

拆成 3 步：照片 → 信息（名称/分类/成色/价格）→ 情况与联系方式，顶部三段进度条。每步 1 屏内完成。

P1-04

清单加载失败会让发布按钮永久禁用，且没有重试入口

publish/index.tsx:71if(templateError||templateLoading){notify(...)}publish/index.tsx:91disabled={...Boolean(templateError)}

用户把内容全部填完，只因为「商品情况清单」接口失败，就再也点不动发布按钮。提示文案写的是「切换分类后可重试」——让用户用切换分类来触发重试，是一个隐藏技巧，不是可发现的交互。

失败态给明确的「重新加载」按钮；同时允许在清单缺失时提交，后端按「未声明」处理，不要让次要信息阻塞主流程。

P1-05

详情页主 CTA 有 5 种文案，点下去会发生什么无法预期

detail/index.tsx:48

同一个按钮会在「复制联系方式 / 等待卖家同意 / 申请未通过 / 已售出 / 我想要·申请联系」之间切换，其中三种是禁用态。用户看到的是「按钮在变」，而不是「商品状态在变」。

主按钮文案固定为「我想要」，状态用按钮上方的副文案或状态 pill 表达；禁用态给出明确原因，而不是把原因塞进按钮里。

P1-06

通知页用营销式长标题占首屏，且没有未读角标

notifications/index.tsx:33title='每一次联系，都由你决定'app.config.ts:13

23px 标题在 375 宽下折成两行，占掉首屏 1/4；而页面真正要传达的是「有几条待处理」。tabBar 也没有 badge，用户不知道有申请进来，只能靠主动点进来看。

标题改「联系申请」+ 副标题「3 条待处理」；segment 上带数量；tabBar 用 Taro.setTabBarBadge 同步未处理数。

P1-07

商品名只显示一行，8–14 字的标题必然被截断

app.scss:74.card-title{white-space:nowrap;text-overflow:ellipsis}

「高等数学教材，上下册」「捷安特校园通勤自行车」在双列卡里一行只能放下 8 个字左右，关键的后半段（册数、型号）被省略——而二手商品恰恰靠这些信息区分。

允许 2 行（-webkit-line-clamp:2），固定两行高度保证卡片等高对齐。

P2

打磨项

4 项 · 建议随迭代做
P2-01

没有 token 层：主色硬编码 15+ 处，字号 14 档、圆角 9 档

#194e41×15 #17231e×6 #f6f5f0×5 圆角 10/11/12/13/14/16/18/20/22

想换主色、做暗色模式、调整体密度，都只能全局搜索替换。间距也散在 5–24 之间几乎每个整数都有，视觉上「差不多但不一样」的错位就是这么来的。

抽出 CSS 变量层（见下一节），字号 7 档、间距 4 的倍数、圆角 5 档。

P2-02

图标用文本字符代替，跨机型字形不一致

⌕◇▤♡ ♥⌄↗＋

这些字符依赖系统字体，安卓上常出现基线偏移、宽度不同、甚至渲染成方框。全角空格（▤　我的发布）在菜单行里还会导致左右不对齐。

换成 16/20/24 三档 SVG 图标，或统一用一套 iconfont。

P2-03

加载态与空态不成体系

app.scss:81.skeleton{height:250px}components.tsx:13◇

骨架屏固定 250px，但真实卡片高度是「图 1:1 + 4 行文字」≈ 240–270px，加载完成会跳一下；空态只有一枚 ◇ 符号，7 个页面文案风格也不统一（「正在加载好物…」「加载好物中…」）。

骨架高度跟真实卡一致；空态统一为「图标 + 一句结论 + 一句下一步 + 一个动作」四段式。

P2-04

没有深色模式

app.config.ts 未声明 darkmode / themeLocation

#f6f5f0 这种高明度米白在夜间非常刺眼，而小程序原生支持 theme.json + @media (prefers-color-scheme: dark)。

token 化之后，暗色只需要覆盖 12 个变量，不需要改任何组件。

改了什么

  1. 删掉 110px 装饰 banner，首屏直接进入搜索 + 商品，同样屏高下多露出近一整行卡片。
  2. 搜索框常驻顶部，与筛选按钮平级；筛选带「已选条件」角标，替代原来的折叠面板入口。
  3. 分类改为带图标的 chips，从 12px 提到 12px + 32px 高度，点击目标变大；右侧留出渐隐暗示可横滑。
  4. 排序常驻为 tab（综合 / 最新 / 价格⇅），一次点击完成，不再三级跳。

  7. 「发布」升为凸起 FAB，把「消息」放进 tab 并带未读角标——发布是低频动作，消息是高频动作。需配 custom-tab-bar。

注意：凸起 FAB 需要自定义 tabBar（app.config.ts 中 custom: true），若本期不改造，可先保留原 4 项结构，仅做字号与间距修正。

  5. 校区与楼栋合并为一行「交易地点」，楼栋选填，少一次必填决策。
  6. 底部双按钮「上一步 / 下一步」，替换原来一屏到底、提交按钮在 3 屏外的结构。
  7. 「存草稿」给用户一个安全出口，降低中途放弃的心理成本。

落地路线

建议按「先修可读性、再调结构、最后补体系」的顺序推进。第一阶段不涉及任何逻辑改动，风险最低、收益最直接。

阶段一 · P0

可读性与触控

纯样式 · 约 1–2 天
  • 9px/10px → 11px，灰色改 #5E6B63
  • 字重 550/650 → 500/600/700
  • 收藏、删除等热区补到 44×44
  • 状态 pill 接语义色
  • 抽出 CSS 变量层（顺带完成）
阶段二 · P1

首页与转化路径

小改结构 · 约 1 周
  • 删 banner、搜索 sticky、排序前置
  • 卡片 2 行标题 + 价格等宽数字
  • 详情页 CTA 与状态语义化
  • 通知页标题、数量、未读角标
  • 发布页三步拆分 + chips
阶段三 · P2

体系与打磨

约 2 周，可并行
  • 图标替换文本字符
  • 骨架屏高度对齐真实卡片
  • 空态四段式统一
  • tabBar 自定义（FAB）
  • 深色模式变量覆盖

验收清单

  • 375 / 390 / 414 三档真机截图对比，无错位
  • 所有正文文字 ≥ 11px，对比度 ≥ 4.5:1
  • 所有可点元素热区 ≥ 44×44pt
  • 全局无 550 / 650 字重
  • 圆角只用 8 / 12 / 14 / 24 / 999
  • 间距全部为 4 的倍数
  • iPhone SE（667 高）首屏可见 ≥ 2 张完整卡片
  • 状态色与状态文案始终成对出现
  • 发布流程每步可返回、可存草稿
  • 清单接口失败不阻塞发布
