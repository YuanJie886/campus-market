# 商品展示与联系方式

当前平台提供同校商品展示与卖家联系方式。后续沟通、价格协商和实际交易由双方通过实际联系方式自行约定，平台不建立交易订单、不预约地点或时间、不确认履约、不记录交易评价或交易履历。

## 卖家选择

发布和编辑商品时，卖家填写手机号、微信号或其他联系方式，并手动选择「公开展示联系方式」。单件、整套打包和批量发布均支持这一选项，默认不勾选；旧商品迁移后也保持不公开。

勾选后，有权查看商品的同校用户可看到联系方式；商品本身的学校、圈子和内容可见范围仍然有效。「公开」不会将圈子商品或跨校商品变为所有人可见。

未勾选时，买家点击「我想要」提交联系申请。卖家在「个人中心 → 联系申请」中同意或拒绝。同意后仅该商品的该买家能够在商品详情页查看联系方式，不授权其他买家或其他商品。申请不改变商品在售状态，不生成订单，同一买家对同一商品重复点击不会重复生成申请。拒绝后不会显示联系方式，也不会重复发送该申请。

卖家关闭公开选项后，只有卖家本人及已获同意的买家仍可查看。申请状态可手动刷新，回到页面时也会刷新。

## API

- `GET /v1/products/{id}/contact-request`：本人对商品的申请，尚未申请时返回 `null`。
- `POST /v1/products/{id}/contact-request`：创建申请，不接受买家或卖家身份字段；身份来自登录会话及商品所有者。
- `GET /v1/contact-requests`：查看本人收到及发出的申请。
- `POST /v1/contact-requests/{id}/decision`：卖家提交 `{ "status": "APPROVED" }` 或 `{ "status": "REJECTED" }`。

所有接口要求登录。后端负责联系方式授权，无权用户的商品响应中 `contact` 为空。批准信息不扩大商品的可见范围。

已撤下用户订单、验货提交、预约地点、档期改约、到达确认、爽约报告、交易评价、交易履历和历史成交参考的公开接口。旧数据保留，不删除历史记录；旧预约中商品迁移为在售，不再被预约订单锁定；订单过期任务不再调度。原有交易闭环文档仅供历史架构参考。

数据库变更位于 `V15__contact_requests.sql`，由 Flyway 在后端启动时执行；Mock 的对应数据迁移版本为 12。
