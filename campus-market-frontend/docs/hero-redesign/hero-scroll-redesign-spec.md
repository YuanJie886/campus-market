# 首页 Hero 滚动叙事改造方案

> 角色：UI 设计师 / 交互设计师
> 范围：`campus-market-frontend` 首页 Hero 区（`HomePage.tsx` MODULE 1 + `index.css` MODULE 1）
> 交付物：本规范 + 高保真可交互原型 `prototype.html`
> 结论：**视觉语言不动，重做滚动的时间结构。** 把「一屏淡出」改成「三幕推进」。

---

## 1. 问题诊断

用户反馈：「首页 Hero 向下滑动时太单调了」。我把它量化了。

### 1.1 实测证据

在 1080×577 视口下抓取滚动全过程的四个节点（见原型对照）：

| 滚动位置 | 滚动进度 | 画面变化 |
|---|---|---|
| 0px | 0% | 基准画面 |
| 150px | 32% | 文字上移 ~16px |
| 300px | 65% | 文字上移 ~32px，略微变淡 |
| 462px（行程终点） | 100% | 文字上移 36px，卡片后退 36px，整体略暗 |

**整个 80vh 的滚动行程，画面上没有任何新元素进入。** 用户滑完一屏，看到的还是同一屏。这就是"单调"的全部原因。

### 1.2 根因：三段代码

```css
/* index.css:193 —— 舞台被拉长到 180vh */
.cm-apple-hero-stage { min-height: 180vh; }

/* index.css:228 —— 内容被钉死在视口顶部，不随内容流动 */
.cm-apple-hero-container { position: sticky; top: 0; min-height: calc(100vh - 60px); }
```

```ts
// HomePage.tsx:117-131 —— 180vh 行程里，只有"位移 + 淡出"两种动作
heroCopyRef.style.opacity = `${Math.max(0, 1 - progress * 1.25)}`;
heroCopyRef.style.transform = `translate3d(0, ${progress * -50}px, ${progress * -80}px) scale(...)`;
heroProductRef.style.transform = `translate3d(${progress * -30}px, ${progress * -36}px, ${progress * -60}px) rotateX(...) rotateY(...)`;
```

一个 180vh 的容器（= 2 倍视口高），里面只放了一屏内容，然后用 80vh 的滚动去驱动 **±50px 的位移和一次淡出**。滚动行程与视觉变化量的比值失衡——用户付出的滚动成本没有换来任何信息回报。

### 1.3 顺带发现的三个真实缺陷

| # | 缺陷 | 证据 | 影响 |
|---|---|---|---|
| A | **首屏主 CTA 被裁出视口** | 滚动 0 时，「探索校园好物」按钮位于视口下沿之外，用户看不到 | 首屏转化入口不可见，P0 |
| B | **排版脆性：标题孤字成行** | `clamp(3.2rem, 6.4vw, 5.8rem)` 在 1080px 宽下断成三行，末行只剩「活。」 | 品牌第一印象受损 |
| C | **滚动进度条永远不可见** | `.cm-apple-hero-scroll-cue` 在 sticky 容器最底部，被裁掉 | 「向下滑动」的引导失效 |

> 缺陷 A 是本次改造必须一并修掉的：无论动效做得多好，首屏看不到按钮就是失败。

## 2. 设计目标

| # | 目标 | 可度量标准 |
|---|---|---|
| 1 | 滚动的每一步都有回报 | 180vh 行程内至少 3 次「新元素入场」事件 |
| 2 | 首屏即可转化 | 主 CTA 在 p=0 时完整可见且可点击 |
| 3 | 用户保有滚动主权 | 不劫持滚动、不用 scroll-snap、任意位置可跳过 |

| 6 | 视觉资产零浪费 | 沿用现有色彩 token、卡片样式、缓动曲线 |

## 3. 核心设计：三幕滚动叙事

### 3.1 概念

**「交接 / The Handover」** —— 首页 Hero 讲述一件闲置物品的三次交接，与产品定位（校园二手循环）同构。

保持 180vh→**300vh** 的舞台长度，但把它切分为三幕，每一幕都有新元素入场：

```
p=0 ──────────────── 0.33 ──────────────── 0.66 ──────────────── p=1
│      第一幕 宣言      │      第二幕 展台      │      第三幕 入场      │
│  · 主标题字错峰入场    │  · 左侧文案整体换幕    │  · 全幅终章面板居中    │
│  · 主 CTA 首屏可见    │  · 卡片从堆叠扇形展开   │  · 信任三柱淡入       │
│  · 数据从 1,200 计数  │  · 校园同心圆雷达浮现   │  · 主 CTA 放大        │
│    到 1,400          │  · 光晕从右上移至中    │  · 背景提亮           │
└──────────────────────┴──────────────────────┴──────────────────────┘
        ↑ 新入场：CTA          ↑ 新入场：2 张卡 + 雷达    ↑ 新入场：三柱 + 终章 CTA
```

**关键设计决策：文字阶梯切换，卡片连续插值。**

- 文案面板用**带位移的交叉淡入淡出**（约 12% 行程完成切换），避免两段文字半透明叠加导致不可读；
- 卡片展台用**连续插值**（`--fan` 变量 0→1），让滚动过程有物理质感。
- 二者节奏不同，观感上"文字在换幕，物件在呼吸"。

### 3.2 滚动时间轴（实现参数）

所有阈值用 `smoothstep(x, a, b)` 归一化，保证进出都有缓入缓出，不会硬切。

| 变量 | 含义 | 区间 | 驱动的视觉 |
|---|---|---|---|
| `--a1` | 第一幕不透明度 | `1 - ss(p, 0.20, 0.33)` | 宣言文案淡出并上移 48px |
| `--a2` | 第二幕不透明度 | `ss(p,0.24,0.37) × (1-ss(p,0.56,0.68))` | 展台文案淡入再淡出 |
| `--y2` | 第二幕纵向位置 | `(1-in)×54 + (out-1)×54` | 从下方 54px 推入，向上方 54px 退出 |
| `--fan` | 卡片展开度 | `ss(p, 0.28, 0.50)` | 堆叠 → 扇形展开 |
| `--collapse` | 展台收拢度 | `ss(p, 0.58, 0.78)` | 卡片缩小上移并淡出 |
| `--grid` | 主网格不透明度 | `1 - ss(p, 0.58, 0.74)` | 双栏主版面退场 |
| `--a3` | 终章不透明度 | `ss(p, 0.62, 0.78)` | 第三幕终章面板登场 |
| `--glow-x/y` | 背景光晕位置 | `74%→50%` / `32%→52%` | 光源从右上移到画面中心 |
| 数据计数 | 顶部在线件数 | `1200 + 200 × ss(p, 0.02, 0.30)` | 首屏数据从 1,200 滚动到 1,400 |

> 数据计数**不从 0 开始**。从 0 计数会让首屏出现「0 件好物在线」这种自相矛盾的状态；从 1,200 起跳既真实又保留了"在增长"的动感。

### 3.3 卡片展台的运动规格

三张卡片绝对定位叠放，用同一个 `--fan` 驱动（数值为最终实现值）：

| 卡片 | 横向 | 纵向 | 旋转 | 缩放 | 不透明度 | 层级 |
|---|---|---|---|---|---|---|
| 左（后） | `-8% → -40%` | `-5% → 4%` | `-7° → -14°` | `0.80 → 0.68` | `0.55 → 1` | 1 |
| 右（后） | `8% → 40%` | `5% → 4%` | `6° → 14°` | `0.79 → 0.68` | `0.55 → 1` | 2 |
| 中（前） | `0` | `0 → -5%` | `0` | `0.93 → 1.00` | `1` | 3 |

**为什么侧卡要缩小到 0.68**：展开时侧卡的几何外延 = `0.40×360 + 360×0.68/2 ≈ 266px`。在 1440px 视口下右侧栏半宽为 292px，因此**不会溢出视口**。如果侧卡不缩小（保持 0.85），外延会达到 297px 并导致右侧卡片被裁切——这是实测出来的边界，不是估算。

**为什么去掉 `preserve-3d`**：初版给中卡加了 `translateZ(70px)` 配合 `transform-style: preserve-3d` 做景深，结果背面卡片的价签会因 3D 排序而穿透到前卡上（命中测试证实 `elementFromPoint` 返回前卡，但渲染层仍有渗透）。改为纯 `z-index` 分层 + 缩放表达景深，行为可预测。

| 元素 | 规范 | 说明 |
|---|---|---|
| Hero 舞台高度 | `300vh`（≤900px 时 `320vh`） | 三幕各占约 1/3 行程 |

| 正文 | `14.5px / 1.85`，`max-width: 42ch` | 中文行长控制在 42 字内 |
| 圆角 | 卡片 24px、胶囊 999px、信任卡 16px | 沿用现有 `--cm-radius-lg` 体系 |

|---|---|

| 主光晕 | `rgba(211,225,203,.20)`（`--cm-moss-soft`） |
| 次级光晕 | `rgba(25,78,65,.6)`（`--cm-moss`） |

| 眉题 | `--cm-moss-soft`，字距 `.19em` |

### 4.4 动效规范

| 参数 | 值 | 理由 |
|---|---|---|
| 主缓动 | `cubic-bezier(.16,1,.3,1)` | 沿用现有 `--cm-ease-spring`，收尾柔和不回弹 |
| 滚动插值系数 | `0.14`（逐帧 lerp） | 比现有 `0.12` 略快，长行程下更跟手 |
| 停止阈值 | `0.0004` | 低于此值直接归位并停掉 rAF，不空转 |
| 幕切换时长 | 约 12% 行程 | 太短显硬、太长则两段文字叠加 |
| 卡片悬停 | `transform .35s` + 图片 `scale(1.05)` | 沿用现有卡片交互 |

**性能约定**：所有动画只碰 `transform` 与 `opacity`；用 CSS 自定义属性做单一数据源（JS 每帧只写 9 个变量，不逐个操作元素），`will-change` 只加在会动的层上。

## 5. 可用性与无障碍

### 5.1 符合用户习惯的六条约定

1. **首屏必有出口**：主 CTA 在 p=0 完整可见。滚动不该是转化的前提。
2. **可跳过**：底部进度轨道提供 ①②③ 三个锚点，点按直接平滑滚动到对应幕；右下角「跳过 · 直达集市」一键越过整个叙事。
3. **不劫持滚动**：不使用 `scroll-snap`，不监听 `wheel` 做 `preventDefault`，不做"必须滑到底才能继续"的强制播放。用户随时可以一口气滚过去。
4. **进度可见**：顶部 2px 进度条 `scaleX` 直接映射滚动进度，让用户知道"还有多少"。
5. **尊重系统偏好**：`prefers-reduced-motion: reduce` 时整段降级为静态排布（取消 sticky 与插值，三幕内容顺序展开，隐藏进度轨道），并由页面上的「减少动效」开关提供手动预览。
6. **键盘可达**：所有幕锚点与 CTA 均为原生 `<button>`，保留 `:focus-visible` 焦点环。

### 5.2 响应式断点

| 断点 | 变化 |
|---|---|
| > 900px | 双栏；卡片展台居右栏中央；信任三柱三列 |
| ≤ 900px | 单栏纵向：文案在上、展台在下；舞台 `320vh`；标题降至 `clamp(1.75rem,7vw,2.4rem)`；隐藏标签胶囊与展台脚注以压缩高度 |
| ≤ 720px | 信任三柱改单列；原型控制条压缩为图标态 |
| `prefers-reduced-motion` | 取消 sticky 与全部插值，内容静态顺序展开 |

> 移动端高度预算是本次最紧的约束：390×844 下，状态栏 + 文案 + 展台 + 进度轨道必须挤进 784px。实测初版溢出 18px 导致顶栏与眉题重叠，通过隐藏标签胶囊（-42px）与压缩正文行高（-10px）解决。

## 8. 与既有 UX 架构方案的关系

`docs/ux-architecture-redesign.md` 的结论是「视觉已经足够好，不要再动它」，并把 Hero 定位为"把营销叙事放在核心任务之前"的 P0 断点。

**本方案与它不冲突，是它的前置步骤。** 那份方案主张把 Hero 移到集市区**之后**并折叠；本方案则先把 Hero 本身改造成"值得看的三幕"，同时通过第三幕的终章 CTA 让它**主动把用户交接到集市**。

两条路可任选，也可叠加：

| 路径 | 做法 | 适用 |
|---|---|---|
| A（本方案） | Hero 保留在首位，用三幕叙事 + 终章 CTA 完成交接 | 品牌表达是产品差异化的一部分，且首屏 CTA 已可见 |
| B（架构方案） | Hero 移到集市之后折叠 | 以"最快找到商品"为唯一目标 |
| A+B | Hero 保留三幕，但舞台从 300vh 压缩到 200vh，并把第三幕终章直接接上集市首屏 | 兼顾两者 |

**推荐 A**：改造后首屏 CTA 已可见（修复了架构方案里"3 屏才见到商品"的核心痛点之一），而 Hero 提供的品牌信任（实名认证 / 当面验货 / 绿色循环）恰恰是二手交易决策的前置条件。
